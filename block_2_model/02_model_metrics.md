# Матрица метрик (Блок 2)

> Это проектные определения для согласования, а не утверждение, что заказчик уже использует именно их. Для финансовой сверки и OTIF требуется бизнес-подтверждение. Все суммы сначала приводятся к базовой единице и рублям по согласованному правилу курса; до подтверждения курс/дата конверсии не считаются окончательными.

| Метрика | Бизнес-определение | Зерно | Источники | Формула | Подводные камни |
|---|---|---|---|---|---|
| OTIF по строкам заказа | Доля строк, полностью принятых в срок и без неприемлемого качества | Строка заказа в выбранной версии/согласованном срезе | `po_headers`, `po_lines`, `receipts` | `eligible_line_count` со своевременным суммарным принятым количеством `>= ordered_qty` и приемлемым качеством / `eligible_line_count` | Нужны правила отмен, частичных поставок, качества, часового пояса, версии строки и допуска по дате. |
| On-time delivery | Доля строк, у которых первое/полное закрытие поставки произошло не позже плановой даты | Строка заказа | `po_lines`, `receipts` | `count(on_time lines) / count(eligible lines)` | Первое поступление не равно полному исполнению; `received_at_utc` надо сопоставить с датой МСК. |
| In-full | Доля строк, где принятое количество достигает заказанного количества | Строка заказа | `po_lines`, `receipts`, `uom` | `count(received_qty_base >= ordered_qty_base) / count(eligible lines)` | Нельзя суммировать разные ЕИ без `factor_to_base`; возвраты/браки могут менять net quantity. |
| Закупочный оборот | Стоимость подтверждённого закупочного объёма в рублях по утверждённому событию признания | Строка заказа или финансовый документ — выбрать один | `po_lines`, `receipts`, `fx_rates` и финансовый источник, если доступен | `SUM(quantity × unit_price × FX)` на выбранном событии признания | В выгрузке нет явного факта бухгалтерского признания; заказанная стоимость не равна финансовому обороту. |
| Средневзвешенная цена за базовую единицу | Цена с весом по количеству после приведения к базовой ЕИ | Номенклатура × поставщик × период | `po_lines`, `items`, `uom`, `fx_rates` | `SUM(qty_base × price_rub_base) / SUM(qty_base)` | Нужны правила для версий, скидок, НДС, курса и нулевых/отрицательных количеств. |
| Отклонение цены от медианы рынка внутри выборки | Процентное отклонение цены поставщика от медианы других поставщиков по той же позиции | Номенклатура × поставщик × период | `po_lines`, `items`, `uom`, `fx_rates` | `(supplier_weighted_price - median(other_supplier_prices)) / median(other_supplier_prices) × 100%` | Медиана считается по сопоставимым базовым ЕИ, валюте и периоду; малые выборки отмечать. |
| Доля поставщика в категории | Доля оборота категории, приходящаяся на поставщика | Категория × поставщик × период | `po_headers`, `po_lines`, `items`, `fx_rates` | `supplier_turnover / category_turnover` | Номенклатура без категории и дубли строк могут искажать знаменатель. |
| Концентрация до 80% | Число крупнейших поставщиков, покрывающих накопительно не менее 80% оборота категории | Категория × период | те же, что для доли | Отсортировать доли по убыванию; найти первый cumulative share `>= 0.8` | Зафиксировать обработку равных долей, неизвестных поставщиков и отрицательных корректировок. |
| Изменение цены QoQ | Изменение сопоставимой средневзвешенной цены между полными кварталами | Номенклатура × поставщик (или категория) × квартал | `po_lines`, `items`, `uom`, `fx_rates` | `(weighted_price_current_q / weighted_price_previous_q - 1) × 100%` | Только полные кварталы; учитывать изменение состава заказов и ЕИ. |
| Исполнение планового объёма | Доля заказанного количества, принятого складом по согласованному срезу | Строка заказа | `po_lines`, `receipts`, `uom` | `SUM(received_qty_base) / SUM(ordered_qty_base)` | Может превышать 100%; перепоставки не следует молча обрезать. |
| Доля строк с проблемами данных | Доля строк, для которых отсутствуют ключевые связи или конверсия | Строка заказа | core + DQ checks | `count(rows with blocking DQ flags) / count(all observed line versions)` | Разделять блокирующие и предупреждающие ошибки; не скрывать исключённые строки. |
| Надёжность поставщика | Категория/класс, действовавший на дату заказа; при необходимости — отдельный рассчитанный KPI | Поставщик × дата/период | `suppliers`, `po_headers` | As-of join по интервалу версии; формула KPI отдельно согласуется | Нельзя подменять исторический класс текущим значением `is_current`. |

## OTIF: разведение «94% против 71%»

Предлагаемая основная версия для пилота: **OTIF по строкам заказа**, знаменатель — строки, не отменённые по согласованному статусному правилу и попавшие в период по согласованной дате. Строка считается OTIF, если к плановой дате (с явно согласованным правилом включения конца дня) принято суммарное количество не меньше заказанного в базовой ЕИ и качество принято. Для частичных поставок OTIF становится истинным только после полного количества; качество должно быть согласовано как критерий pass/fail.

Вторая цифра может получаться, если считать каждое событие/поставку, учитывать только своевременность первой приёмки или исключать частичные/отменённые строки иначе. Это **объясняющие гипотезы**, не установленная причина расхождения. Проверка — пересчитать обе формулы на одном и том же наборе строк и вывести список строк, где классификация отличается, затем сверить выборку с логистикой и категорийным менеджментом.

```sql
-- Каркас сравнения определений; сначала согласовать статус отмены,
-- правило сопоставления версий и перевод qty в базовую ЕИ.
WITH line_scope AS (
  SELECT order_id, line_no, planned_delivery_date, qty AS ordered_qty, status
  FROM core_po_line_version
),
receipts AS (
  SELECT order_id, line_no,
         SUM(qty_received) AS received_qty,
         MIN(received_at_utc) AS first_receipt_utc,
         MAX(received_at_utc) AS last_receipt_utc
  FROM core_fact_receipt
  GROUP BY order_id, line_no
)
SELECT
  COUNT(*) AS eligible_line_count,
  SUM(CASE WHEN r.received_qty >= l.ordered_qty
                AND date(r.last_receipt_utc) <= date(l.planned_delivery_date)
           THEN 1 ELSE 0 END) AS candidate_otif_lines
FROM line_scope l
LEFT JOIN receipts r USING (order_id, line_no)
WHERE l.planned_delivery_date IS NOT NULL;
```

> В SQL-каркасе выше сравнение единиц намеренно не считается финальным: без конверсии ЕИ и правил UTC↔МСК это только проверка структуры, не официальное значение OTIF.
